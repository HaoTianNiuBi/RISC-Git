# 02 需求说明

> 本文档定义 RV-Doctor 第一版（MVP）做什么、不做什么，以及每项功能的验收标准。
> 架构与模块划分见 [03-系统架构设计](03-系统架构设计.md)。

---

## 1. 用户故事

| 编号 | 用户故事 |
|---|---|
| US1 | 作为学生，我想粘贴一段 C 代码并点击"体检"，看到它在 RISC-V 上执行了多少条指令、什么类型指令最多，这样我能直观理解代码的 RISC-V 成本。 |
| US2 | 作为学生，我想让平台自动优化我的代码，并且明确告诉我：改了什么、为什么这样改、可信度多少、优化后正确性和指令数的变化，这样我敢信这个结果。 |
| US3 | 作为开发者，我想对比同一份代码在不同优化等级（-O0 ~ -Os）和不同架构（RV32I/RV64I/RV64GC）下的指令统计，为编译参数选择提供依据。 |
| US4 | 作为比赛评委，我想看到每个性能数字的来源（编译日志、运行输出、trace 解析 JSON），确认没有数据造假。 |
| US5 | 作为教师，我想用内置基准程序一键演示"低效写法 vs 优化写法"的指令数差异，作为可视化教学素材。 |
| US6 | 作为用户，当 AI 的修改编译失败或改变程序输出时，我希望平台自动回滚并如实告诉我失败原因，而不是给我一个"看起来更快"的错误版本。 |

## 2. MVP 功能需求（第一版范围）

### FR1 代码输入

| 项 | 说明 |
|---|---|
| 描述 | 支持两种输入方式：① 网页文本框直接粘贴源码；② 上传文件。上传类型：`.c`、`.cpp`、`.s`（汇编）、`.elf`（已编译的 RISC-V 程序，跳过编译直接分析）。 |
| 约束 | 单文件大小 ≤ 512 KB；`.elf` 必须是 RISC-V 架构 ELF（用 `file`/objdump 校验架构字段），否则拒绝并给出明确提示。 |
| 输出 | 落盘到本次任务的隔离工作目录 `workdir/<task_id>/`，路径贯穿后续所有步骤。 |
| 验收标准 | 粘贴与上传均可用；上传 `.txt` 会被拒绝并提示；`.elf` 能被识别为 RV64/RV32 并进入分析流程。 |

### FR2 RISC-V 编译

| 项 | 说明 |
|---|---|
| 描述 | 调用 xPack `riscv-none-elf-gcc` 将源码编译为裸机 ELF。可选架构：`RV32I`（`-march=rv32i -mabi=ilp32`）、`RV64I`（`-march=rv64i -mabi=lp64`）、`RV64GC`（`-march=rv64gc -mabi=lp64d`）。可选优化等级：`-O0/-O1/-O2/-O3/-Os`。 |
| 约束 | 必须使用 `subprocess` **参数列表**方式调用（禁止 shell 字符串拼接）；编译超时默认 60 s；自动附加半主机运行时（`--specs=rdimon.specs`）与链接地址参数（详见 03/04 文档）。 |
| 输出 | ELF 文件、完整编译日志（`build.log`）、反汇编文件（`disasm.txt`，由 `riscv-none-elf-objdump -d` 生成）。 |
| 验收标准 | 编译错误时返回结构化错误（非空 stderr + 退出码），前端展示编译日志；10 个内置基准在 3 架构 × 5 优化等级矩阵中全部编译通过（multilib 支持以 M0 实测为准，见 08 风险 T4）。 |

### FR3 程序运行与统计

| 项 | 说明 |
|---|---|
| 描述 | 用 `qemu-system-riscv64/32` 裸机运行 ELF（semihosting I/O），同时开启 trace 日志；解析日志得到统计结果。统计项：① 动态指令总数；② 指令类别分布（整数算术 / 访存 / 分支 / 无条件跳转 / 乘除 / 浮点 / 系统·其他）；③ 分支指令数、加载/存储指令数；④ 函数调用次数（`jal/jalr` 写 ra 计数）；⑤ 静态指令数与每函数指令数（来自反汇编）；⑥ 程序 stdout 与退出码；⑦ 相对运行时间（同配置多次运行取中位数，仅作参考值）；⑧ 能耗估算分（类别计数 × 可配置权重，附免责声明）。 |
| 约束 | 动态指令计数开启逐条执行模式（QEMU≥10：`-accel tcg,one-insn-per-tb=on`；8.1~9.x：`-one-insn-per-tb`）保证精确；运行超时默认 120 s；stdout 缓冲上限 1 MB；基准程序动态指令规模控制在约 10^6 量级。 |
| 输出 | `metrics.json`（结构见 03 文档数据模型）、运行 stdout、trace 原始日志留存于工作目录。 |
| 验收标准 | 同一 ELF 同一输入**连续运行两次，动态指令总数与类别分布完全一致**（确定性校验）；所有统计数字可从留存的 trace 日志复核。 |

### FR4 优化建议

| 项 | 说明 |
|---|---|
| 描述 | 双引擎：① **规则引擎**（`rules.py`，确定性，不依赖网络）：9 条固定规则，每条输出规则编号、问题位置、问题说明、RISC-V 层面证据（汇编片段/指令计数）、优化建议、风险等级、预期收益、置信度；② **LLM 建议**（`llm_agent.py`，DeepSeek 接口）：输入源码 + 关键汇编摘录 + 指标 JSON + 规则引擎发现，输出结构化建议（JSON Schema 校验，不合格直接丢弃）。 |
| 约束 | LLM 上下文中**不含任何编造的数字**，指标均来自 FR3 实测；LLM 不直接改用户文件，只产出"修改说明 + 完整修改后源码"候选；网络不可用或未填写 Key 时，自动降级为仅规则引擎，界面明确标注当前模式。 |
| 输出 | `findings.json`（规则发现）与 `suggestions.json`（LLM 建议），每条含统一评分字段。 |
| 验收标准 | 每个内置基准至少触发 1 条规则且证据字段非空；LLM 建议缺字段/超长/JSON 非法时被自动拒绝并记录。 |

### FR5 自动验证（闭环核心）

| 项 | 说明 |
|---|---|
| 描述 | 对每个候选修改版本自动执行：重新编译 → 运行 → **stdout 与原版逐字符比对**（规则见 06 文档）→ 重新统计动态指令 → 综合判定。判定规则：编译成功 且 输出一致 且 （动态指令数下降 或 能耗分下降）→ **ACCEPT** 并生成对比报告；否则 **REJECT** 并自动回滚（保留原版文件与全部失败证据）。 |
| 约束 | 状态机见 06 文档（PROPOSED→COMPILED→TESTED→MEASURED→ACCEPTED/REJECTED）；验证结果与失败原因必须写入报告，不许静默丢弃。 |
| 输出 | `verdict.json`、对比报告 `report.md`（优化前/后指标表 + 变化率 + 结论）。 |
| 验收标准 | 至少 2 个内置基准能走完 ACCEPT 全流程；至少构造 1 个必然失败的修改，验证 REJECT + 回滚路径；报告中每个数字可在工作目录复核。 |

## 3. 扩展需求（MVP 之后，按优先级）

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| FR6 | 对比报告导出 | 报告导出为 Markdown / HTML 文件 | 高（M6 实现） |
| FR7 | 编译参数推荐 | 同一代码自动扫 -O0~Os × 架构，推荐指令数最少的组合 | 中 |
| FR8 | 批量基准跑分 | 一键跑全部内置基准并汇总表 | 中 |
| FR9 | 运行时热点函数排名 | 结合 trace 与符号表给出每函数动态指令占比 | 低（trace 解析已具备数据，差符号关联） |

## 4. 非功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR1 | 可复现性 | 相同输入 + 相同配置 → 指标结果完全一致；工具链与 QEMU 版本锁定并记录（04 文档版本登记表） |
| NFR2 | 安全性 | 外部命令一律 `subprocess` 参数列表；工作目录按任务隔离；超时与输出上限防挂死；源码作为数据对待，不 `eval` |
| NFR3 | 可移植性 | 路径用 `pathlib`，兼容含中文/空格的路径；配置集中于 `.env` + `config.toml` |
| NFR4 | 响应性能 | 单基准"体检"端到端 ≤ 60 s（受 trace 解析速度影响，M2 实测后校准） |
| NFR5 | 降级可用 | 无 LLM API 时仅规则引擎可用；无 trace 时仅静态分析可用并明确标注"静态估算" |
| NFR6 | 可测试 | 每个模块有 pytest 单元测试；trace 解析器有基于固定样例日志的测试（≥ 5 个用例） |

## 5. 输入输出规格

### 输入

| 类别 | 取值 |
|---|---|
| 文件类型 | `.c` / `.cpp` / `.s` / `.elf` |
| 架构 | RV32I（ilp32）、RV64I（lp64）、RV64GC（lp64d） |
| 优化等级 | -O0、-O1、-O2、-O3、-Os |
| 语言 | 源码以 C 为主（MVP）；C++ 仅支持无异常/无模板重特性的基础子集，不确定行为以编译结果为准 |

### 输出

| 产物 | 格式 | 说明 |
|---|---|---|
| `metrics.json` | JSON | 静态 + 动态全量指标（schema 见 03 文档） |
| `findings.json` | JSON | 规则引擎发现列表 |
| `suggestions.json` | JSON | LLM 建议列表（含可信度/收益/风险/依据） |
| `verdict.json` | JSON | 验证闭环结论与状态轨迹 |
| `report.md` | Markdown | 优化前后对比报告（界面可渲染，可导出） |
| `build.log` / `disasm.txt` / `stdout.txt` / `trace.log` | 文本 | 原始证据，全部留存 |

## 6. 明确不做的（Out of Scope，第一版）

| 不做 | 原因 |
|---|---|
| 真实功耗 / 温度 / 主频测量 | 无硬件；只做相对能耗估算（见 01 文档边界声明） |
| 缓存时序、周期精确仿真 | QEMU TCG 不建模缓存；如未来需要周期级数据，另评估 Spike/ gem5 扩展 |
| 多线程 / 并行程序分析 | 裸机单核环境，无并行语义 |
| 操作系统相关分析（系统调用、内核模块） | 裸机 semihosting 环境 |
| 修改 `.elf`（二进制改写优化） | 第一版只重新编译源码级候选 |
| 支持任意 C++ 特性（模板元编程、异常、RTTI） | 裸机工具链支持有限，第一版聚焦 C |
| 多文件工程 / 构建系统解析 | 第一版单编译单元为主，多文件列为后续扩展 |

## 7. 术语表

| 术语 | 定义 |
|---|---|
| 动态指令数 | 程序一次运行中实际执行的指令总条数，循环体按迭代次数累计。本项目核心性能指标，确定性可复现 |
| 静态指令数 | 反汇编后代码段中的指令条数，与执行次数无关 |
| 指令类别 | 按助记符划分：整数算术（add/sub/and/or/shift 等）、访存（lb/lh/lw/ld/sb/…）、条件分支（beq/bne/blt/…）、无条件跳转（jal/jalr）、乘除（mul/div/rem）、浮点（f 开头指令）、系统与其他（ecall/ebare/fence 等） |
| semihosting | 裸机程序通过 `slli/ebreak/srai` 特征指令序列向模拟器请求宿主 I/O（printf、exit 等）的调试协议，QEMU 以 `-semihosting` 开启 |
| TCG | QEMU 的 Tiny Code Generator，指令级二进制翻译引擎；不模拟缓存与流水线时序 |
| TB（Translation Block） | TCG 的翻译块单位；逐条执行模式下 TB 即单条指令，是精确计数的实现基础 |
| trace 日志 | QEMU `-d in_asm,exec,nochain -D <file>` 输出的翻译/执行日志，用于离线统计动态指令 |
| 软浮点 | 目标 ABI 无硬件浮点（如 lp64）时，编译器生成对 libgcc 软浮点例程（`__mulsf3` 等）的调用 |
| multilib | 交叉编译器为多种 `-march/-mabi` 组合预编译的运行库集合；用 `riscv-none-elf-gcc -print-multi-lib` 查看 |
| 半主机运行时 | newlib 的 `rdimon.specs`，提供基于 semihosting 的 crt0 与 libc I/O |
| 验证闭环 | PROPOSED→COMPILED→TESTED→MEASURED→ACCEPTED/REJECTED 的候选代码审查状态机（见 06 文档） |
| 能耗估算分 | 指令类别动态计数 × 可配置权重的加权求和，仅用于相对比较，不替代硬件测量 |
