【一、这个项目是什么】

输入一段 C 源码，RV-Doctor 会自动完成：
  交叉编译为 RISC-V 裸机程序 → QEMU 模拟器逐条指令运行
  → 统计动态指令数/类别分布/函数调用 → 规则引擎定位性能瓶颈
  → 生成优化候选 → 自动验证（编译✓ 输出一致✓ 指令实测下降✓）
  → 生成优化前后对比报告；任何一步失败自动回滚并给出原因。

所有性能数字均来自真实工具链（GCC 15.2.0 + QEMU 11.1.0）实测，
不存在任何编造数据；能耗分为指令类别加权估算，仅用于前后对比。

【三、如何打开项目（三种方式）】

◆ 方式 A：网页界面（推荐，日常使用）

  ★ 最简单：双击项目根目录下的"启动体检台.bat"——自动启动服务并
    打开浏览器；想停止时双击"停止体检台.bat"或直接关闭命令行窗口。

  手动方式：
  1. 打开命令提示符（Win+R 输入 cmd）或继续用当前终端；
  2. 进入项目目录并启动：
       D:
       cd D:\RISC-V-first
       .venv\Scripts\python -m streamlit run app.py
  3. 终端显示 "Local URL: http://localhost:8501" 后，
     浏览器会自动打开（或手动访问 http://localhost:8501）；
  4. 停止服务：在终端按 Ctrl+C。

  注意：若 8501 端口已被占用（提示 Port 8501 is not available），
  说明已有一个 RV-Doctor 正在运行，直接访问 http://localhost:8501
  即可；或换端口启动：
       .venv\Scripts\python -m streamlit run app.py --server.port 8502

◆ 方式 B：一键自检（验证环境与功能完整性）

       cd D:\RISC-V-first
       scripts\run_all_checks.bat

  全绿输出 ALL CHECKS PASSED；约 1~2 分钟（含真实编译与 QEMU 运行）。

◆ 方式 C：命令行端到端（不开网页，直接跑业务链）

  全链路巡检（体检→快照回归→规则取证→优化验证→报告）：
       .venv\Scripts\python -X utf8 scripts\e2e_check.py

  验证闭环演示（规则引擎模式，无需 LLM）：
       .venv\Scripts\python scripts\m5_demo.py

【四、网页界面操作步骤】

  第 1 步：左侧栏选择编译配置
      - 目标架构：rv64gc（含硬件浮点）/ rv64i / rv32i
      - 优化等级：-O0 至 -Os（缺省 -O0，最能暴露源码问题）
      - 确定性校验：保持勾选（同一程序跑两遍，指令数必须一致）

  第 2 步：提供待分析代码（两种方式任选）
      - "粘贴代码"页签：直接在文本框粘贴 C 源码（有示例代码）
      - "上传 .c 文件"页签：上传单个 .c 文件（≤1 MB）
      - 想用内置基准：把 benchmarks\ 目录下 b01~b10 中任一
        .c 文件上传即可（如 b09_strlen_loop.c）

  第 3 步：点击"🩺 一键体检"按钮（约 10~30 秒）

  第 4 步：阅读结果
      - 指标卡片：动态指令总数、静态指令数、调用次数、能耗估算分
        （"指标"页签内，霓虹发光卡片）
      - 图表：指令类别分布环形图（暗色霓虹配色）
      - 程序输出："程序输出"页签内的终端风格面板，显示 QEMU
        实际运行打印的内容
      - 步骤轨迹：编译→运行→统计各步骤的耗时时间线
      - 任务号与证据目录：workdir\<任务号>\ 下有全部原始产物
        （build.log / disasm.txt / stdout.txt / trace.log / metrics.json）

  命令行生成优化对比报告（体检闭环后）：
      .venv\Scripts\python -m reports.report 优化前metrics.json 优化后metrics.json verdict.json -o report.md

【六、结果怎么读（指标口径）】

  动态指令总数   程序一次运行实际执行的指令条数（核心指标，确定性：
                 同程序同输入两次运行完全一致）。只统计程序区，
                 不含 QEMU 引导 ROM。
  分支/访存/调用 动态指令的类别子集；调用指 jal/jalr 写 ra 的次数。
  静态指令数     反汇编后代码段指令条数（不含执行次数）。
  耗时           参考值（受宿主机负载影响），仅供参考，已标注。
  能耗估算分     指令类别 × 可配置权重（config.toml）的相对估算，
                 仅用于优化前后趋势对比，不代表真实硬件功耗。
  缓存友好性     仅静态提示；QEMU 不模拟缓存时序，无实测值。

【七、开启 AI 优化建议（可选，需联网）】

  1. 完成一次“一键体检”后，在页面下方「优化建议（规则 + AI）」区域
     展开“🔑 DeepSeek 接入配置”；
  2. 填入你的 DeepSeek API Key（在 platform.deepseek.com 获取）；
     Base URL 与模型名已有默认值，一般无需修改；
  3. 点击“生成优化建议并验证”。

  API Key 仅保存在当前浏览器会话内存中：不写入任何文件、不进仓库，
  刷新页面后需重新填写。未填写时一切功能照常可用（规则引擎模式），
  界面会标注当前模式。
  隐私提示：开启后用户源码会随请求发送至 DeepSeek。

【八、常见问题 FAQ】

  Q1 浏览器打开 http://localhost:8501 是空白/连接被拒？
     服务未启动或已停止。按方式 A 重新启动；看终端有无报错。

  Q2 终端中文乱码？
     先执行 chcp 65001 切换 UTF-8 代码页。

  Q3 体检按钮转圈很久？
     正常约 10~30 秒（真实编译 + QEMU 逐条指令运行 + 两次确定性
     校验）。超过 2 分钟多是死循环程序被超时机制拦截并报错回滚。

  Q4 提示 Port 8501 is not available？
     已有实例在运行，直接用浏览器访问；或用 --server.port 换端口。

  Q5 上传 .c 体检报"输出不一致/编译失败"？
     这正是验证闭环在工作：代码无法编译或行为异常都会被拦截并
     给出原因与日志路径。查看 workdir\<任务号>\build.log 定位。

  Q6 想恢复出厂基准数据？
     基准冻结：.venv\Scripts\python scripts\freeze_benchmarks.py
     （会用独立参考实现复核后才允许覆盖）。

  Q7 命令行里 python 不是 venv 里的？
     始终用 .venv\Scripts\python 前缀，避免污染全局环境。

【九、数据可信度说明（本项目的红线）】

  1. 界面与报告中的每个数字都能在 workdir\<任务号>\ 的原始产物中
     复核（trace.log 可手工数出动态指令数）；
  2. 指标先落盘（metrics.json）再渲染，界面不做任何现场估算；
  3. LLM 只产出建议与候选代码，一切数字以复测为准；
  4. 优化候选必须通过"编译成功 + 输出逐字符一致 + 动态指令实测
     下降"三关，任何一关失败自动回滚并保留失败证据；
  5. 能耗分与耗时为估算/参考值，界面与报告均附带免责声明。
