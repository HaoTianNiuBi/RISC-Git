# 01 项目概述

> 本文档回答三个问题：这个项目是什么、为什么值得做、边界在哪里。
> 需求细节见 [02-需求说明](02-需求说明.md)，技术实现见 [03-系统架构设计](03-系统架构设计.md)。

---

## 1. 一句话介绍

**RV-Doctor** 是一条「先测量、再让 AI 说话、最后用证据收口」的 RISC-V 诊断流水线，现在跑在 K1 上：对着耳麦说一句话，板内完成语音识别与意图判定，执行一次真实的矩阵乘法体检，把实测结果直接显示在触屏上；同一套方法论向下延伸到主机侧——输入 C 源码，自动交叉编译、QEMU 裸机运行、解析指令 trace 得到动态指令统计，再由规则引擎与大模型给出优化建议，并用「编译 → 输出一致 → 实测下降」三关验证，失败自动回滚。

## 2. 项目性质

- **端侧实机为主**：K1 MUSE Pi Pro（Bianbu LXQt），本地 ASR + 本地 LLM，全程不出网；音频不上传、源码不上传。
- **主机侧为子系统**：Windows 上通过 RISC-V 交叉编译器 + QEMU 完成指令级统计与优化闭环，用于在没有硬件时复现同一套测量方法。
- **软件形态**：Python（板端 `edge_terminal/`、主机侧 Streamlit + 命令行工具链）+ 触屏网页界面 + 官方 SDK / 模型。

## 5. 核心工作流（用户视角）

```
上传/粘贴代码 ──► 选择架构与优化等级 ──► 【RISC-V 性能体检】
       │                                      │
       │                        编译 → QEMU 运行 → 指令统计
       │                                      │
       │                     体检报告：指令总数/类别分布/热点函数/能耗估算分
       │                                      │
       └────────────────────► 【自动优化】      │
                                  │            │
                        规则引擎 9 条 + LLM 建议（各带可信度/收益/风险/依据）
                                  │
                        自动修改代码 → 重新编译 → 运行测试 → 输出比对
                                  │
                     ┌────────────┴────────────┐
                全部通过且指令数下降        任何一步失败
                     │                          │
              生成前后对比报告              自动回滚，报告失败原因
```

## 6. 四大创新点

### 创新点一：从"AI 写代码"升级为"AI 验证代码"

不只让 AI 生成优化代码，而是建立面向 RISC-V 程序的 **"分析 → 生成 → 验证 → 回滚"闭环**。AI 产生的任何修改都必须自动通过：

1. 能否编译通过；
2. 能否通过测试（输出与基准完全一致）；
3. 优化后动态指令数是否真的下降（以实测为准）；
4. 任何一步失败 → 自动回滚到原始版本，并保留失败记录作为证据。

这让项目的可信度从"AI 说了算"变成"流水线说了算"。

### 创新点二：面向 RISC-V 指令特征的优化

平台不只看源码，还分析真实的 RISC-V 汇编与指令执行 trace，例如：

```asm
lw      a5,0(a0)        # 访存
addi    a0,a0,4         # 指针递增
add     a4,a4,a5        # 累加
bne     a0,a1,loop      # 循环分支
```

可识别的问题类型：循环中分支过多、内存访问次数过多、循环不变量重复加载、函数调用过于频繁、浮点操作在无 F/D 扩展的架构上退化为软浮点库调用、类型转换冗余（sext.w/zext 系模式）、寄存器溢出导致的栈访问、编译参数不足等。每条发现都附带汇编层面的证据。

### 创新点三：优化建议可信度评分

每一条建议（无论来自规则引擎还是 LLM）都输出统一的结构化评分，拒绝黑盒：

```
建议：将循环边界 strlen(s) 的计算移出循环
可信度：87%      预期收益：中等      风险：低
依据（全部来自实测/静态解析）：
  - 该循环动态执行 10,000 次（trace 解析）
  - strlen 在循环体内被重复调用 10,000 次（call 计数）
  - 每次调用约 12 条指令（反汇编）
  - 预计减少动态指令约 120,000 条
```

### 创新点四：性能—能效联合视角（绿色计算）

建立**可配置的软件能耗估算模型**：

```
估算能耗分 = Σ (指令类别动态计数 × 该类别权重)
```

权重（整数/访存/分支/乘除/浮点等）存放于配置文件，可调整。明确声明：

> 本项目提供基于指令类别权重的相对能耗估算，用于比较优化前后的能耗趋势，不替代真实硬件功耗测试。

该功能把项目从"代码优化工具"提升为"面向 RISC-V 的性能—能效联合优化工具"。

## 7. 相关工作与竞品对比

> 调研时间：2026-09。竞品动态以官方发布为准；本表用于答辩时回答"市面上有没有类似的"。

**结论先行**：数指令、跑模拟、AI 改代码——每个单点市面上都有人做，但把它们串成"体检 → 开方 → 复查 → 不过就退货"完整闭环、零硬件门槛、开箱即用的产品，目前没有。本项目的创新不在单项技术，而在**编排与可信度**。

| 类别 | 代表 | 能做到 | 缺什么 | 与 RV-Doctor 的差异 |
|---|---|---|---|---|
| 在线汇编查看 | Compiler Explorer（godbolt.org） | 显示代码对应的 RISC-V 汇编 | 不实际运行、无动态指令统计、无优化建议 | 相当于只拍 X 光片；我们出完整诊断报告并负责"治疗" |
| 专业模拟器 | Spike（官方）、gem5、Codasip SIM-V / MachineWare | 高速/高保真模拟 | 输出原始日志需自行解析，多面向芯片公司，部分商业订阅、仅 Linux | 我们把"解析 + 统计 + 可视化"做成开箱即用，且 Windows 原生零配置 |
| 硬件追踪分析 | SEGGER J-Trace / Ozone、Lauterbach Trace32 | 基于真实硬件的精确追踪 | 需购买开发板 + 调试器 + 授权（数千至数万元） | 我们零硬件，免费软件路线；以模拟器确定性统计换取"零门槛" |
| 学术原型 | Prof5（IEEE，带能耗模型的 RISC-V profiler） | 功能仿真 + 能耗/时序模型 | 论文原型，无产品化界面、无 AI 优化闭环 | 我们把"能耗相对估算 + AI 建议 + 验证回滚"做成可用工具 |
| AI 编程助手 | Copilot、Cursor | 生成/修改代码 | 不保证正确、不证明变快、无实测证据 | 我们的三关验证（编译/输出一致/指令实测下降）+ 自动回滚兜底 |
| AI 性能优化 | CodeFlash（AI 改代码 + 基准验证闭环） | 思路上最接近的"验证闭环" | 面向 Python/x86 云环境，不触达 RISC-V 与指令级 | 我们专注 RISC-V 指令级统计，且裸机/嵌入场景可用 |

**答辩一句话口径**：单项技术都有人做；我们的贡献是面向 RISC-V 的可信优化流水线——每个"变快了"都有可复核的运行证据，每次改坏都有自动回滚的记录。

## 8. 与普通"AI 问答项目"的差异

| 维度 | 普通 AI 问答项目 | RV-Doctor |
|---|---|---|
| 交互模式 | 提问 → AI 回答 | 程序分析 → RISC-V 执行 → 性能统计 → AI 建议 → 自动修改 → 正确性验证 → 证据报告 |
| AI 角色 | 内容生成者 | 流水线中的一个环节，产出受闭环约束 |
| 数字来源 | AI 生成（可能编造） | 全部来自真实编译/运行/日志解析 |
| RISC-V 含量 | 往往只是聊天主题 | 编译、ABI、指令集、模拟器、trace 解析贯穿全流程 |
| 失败处理 | 无 | 编译/测试/性能任一失败即自动回滚 |

## 9. 边界声明（诚实原则）

| 声明 | 说明 |
|---|---|
| 纯软件，无硬件 | 不测量、不声称测量任何真实芯片的功耗、温度、主频 |
| 能耗是估算 | 见创新点四的免责声明，界面与报告必须附带 |
| TCG 不模拟缓存 | QEMU TCG 是指令级模拟，不模拟缓存时序。"缓存友好性"分析只作为静态提示呈现，**不作为实测指标** |
| 时间指标弱化 | 主指标是确定性的**动态指令数**（同一输入两次运行结果完全一致）；墙上时间仅作相对参考（多次取中位数） |
| 相对结论 | 优化结论限于"同基准、同架构、同输入下的指令数/能耗分对比"，不外推为绝对性能 |

## 10. 名词速查

| 术语 | 含义（详见 02 文档术语表） |
|---|---|
| 动态指令数 | 程序运行过程中实际执行的指令总条数（含循环重复执行），本项目的核心性能指标 |
| 静态指令数 | ELF 反汇编后代码段中的指令条数（不含执行次数） |
| semihosting | 裸机程序通过约定的指令序列调用模拟器宿主 I/O（printf/exit）的机制 |
| TCG | QEMU 的二进制翻译引擎 |
| 软浮点 | 目标架构无 F/D 扩展时，浮点运算退化为 libgcc 软件例程（如 `__mulsf3`） |
| trace 日志 | QEMU `-d` 选项输出的执行日志，本项目用于统计动态指令 |
