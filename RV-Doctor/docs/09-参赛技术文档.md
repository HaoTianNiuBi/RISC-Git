## 1. 项目简介

**RV-Doctor** 是一个面向 RISC-V 的 AI 代码性能诊断与自动优化平台：输入 C 源码，平台自动完成
交叉编译、QEMU 裸机模拟运行、指令级统计，识别性能瓶颈后由"规则引擎 + 大模型"给出带可信度
评分的优化建议并自动修改代码，再通过"编译 → 测试 → 输出比对 → 指标对比"的**验证闭环**证明
优化正确且真的变快，任何一步失败则自动回滚。

- **纯软件、无硬件依赖**：全部工作在 Windows 原生环境完成（xPack RISC-V GCC 15.2.0 +
  QEMU 11.1.0 + Python 3.14 + Streamlit），不需要开发板，不需要 WSL/Linux。
- **赛事对应**：第二届 CIE 全国 RISC-V 高水平创新及应用大赛（高校赛道），覆盖大赛
  "编译器 / 模拟器 / 工具软件 / 软件生态"主题方向。

**端到端数据流（10 步）**：接收源码 → 编译 → 反汇编/静态统计 → QEMU 运行 → trace 解析 →
指标聚合 → 规则分析 → LLM 建议（可降级）→ 候选验证（状态机）→ 对比报告。
每次任务使用独立任务目录，失败产物也完整保留，报告中每个数字可溯源到落盘文件。

## 3. 关键技术实现

### 3.1 Windows 原生路线：qemu-system 裸机 + semihosting

QEMU 的 linux-user 模式没有 Windows 原生版本，这是技术选型的分叉点。本项目采用
**qemu-system-riscv64/32 + `-bios none` 裸机 + newlib semihosting** 路线：程序通过
`--specs=semihost.specs` 链接半主机运行时，printf/exit 经由约定指令序列落到宿主 I/O，
配合自研最小启动代码 `rvcrt0.S`（设 gp/sp、清 BSS、使能 FPU、关闭 CLINT 定时器中断）。

### 3.2 动态指令精确计数：one-insn-per-tb + trace 解析

开启逐条执行（QEMU ≥ 10 用 `-accel tcg,one-insn-per-tb=on`）后每个翻译块只含一条指令，
`-d in_asm,exec,nochain` 日志中每条 TB 执行记录即对应一条真实执行的指令：

- `IN:` 段提供 PC → 助记符映射（静态翻译记录）；
- `Trace` 行提供逐条执行记录（动态计数来源）；
- 两者结合得到**精确的动态指令总数与七类类别分布**（整数/访存/分支/跳转/乘除/浮点/系统）。

**确定性红线**：统计只依赖日志内容本身，同一 ELF 两次运行的动态指令数与类别分布
**完全相等**（06 文档 §5.1，测试强制校验）。主指标因此选择动态指令数而非墙上时间——
前者可复核、可回归，后者受宿主负载影响只能作参考值。

开发中实测锁定并适配了三个格式关键点（均有固定样例日志测试防回归）：

1. **exec 行 PC 字段自适应定位**：不硬编码版本偏移，用 IN: 段 PC 全集交叉验证自动定位，
   同一解析器兼容 QEMU 8.x/9.x/11.x 日志布局；
2. **符号注解行**：GCC 产物带符号表时 QEMU 11 会在行尾附加符号名（`IN: _exit`、
   `...] _exit`），必须正确解析（该缺陷曾导致漏计 84% 的指令，已由真实 trace 夹具锁定）;
3. **引导 ROM 剔除**：QEMU virt 板卡内置引导 stub 与被测程序无关且计数抖动
   （复位向量首条偶发重复执行），动态统计只计 DRAM 区（≥0x80000000）执行，
   剔除量进入诊断字段。

### 3.3 半主机输出的双通路捕获（Windows 实测发现）

Windows 版 QEMU 11.1.0 的半主机输出有**两条互不相通的通路**：`SYS_WRITE0` 落在
chardev/stderr，而 newlib printf 走的 `SYS_WRITE(fd=1)` 固定进进程 stdout。
运行器以"文件 chardev + 进程 stdout"双通道捕获拼接，配合 `-serial none` 消除
stdio 串口在 subprocess 管道下的退出挂死竞态——保证任意基准的程序输出零丢失。

### 3.4 验证闭环状态机（核心创新）

```
PROPOSED → 编译 → COMPILED → 输出比对 → TESTED → 确定性校验 → MEASURED → 指标对比 → ACCEPTED
    └──────── 任一步失败 ────────→ REJECTED（自动回滚原版文件，保留失败证据）
```

ACCEPT 条件：编译成功 **且** stdout 与 golden 一致 **且**（动态指令数下降 **或** 能耗分下降）。
原版源码永不覆盖；多个候选通过时取动态指令数最小者。判定数据全部来自实测 metrics.json。

### 3.5 LLM 建议的可信度约束

LLM 经 DeepSeek 接口接入（base_url/api_key/model 由用户在界面填写，仅存会话内存），上下文中的数字全部
来自实测 JSON；输出经 JSON Schema 校验，不合法建议直接丢弃并记录。**LLM 只给建议与候选
源码，不给任何数字**——最终以复测为准；未配置 API 时全流程以"规则引擎模式"可用（显式标注）。

## 4. 四大创新点

1. **从"AI 写代码"升级为"AI 验证代码"**：AI 的任何修改必须通过编译、输出一致、指标实测
   下降三关，失败自动回滚——可信度从"AI 说了算"变成"流水线说了算"。
2. **面向 RISC-V 指令特征的优化**：分析真实汇编与执行 trace，识别软浮点退化、循环不变量
   重复计算、冗余类型转换、寄存器溢出等 9 类问题（R1~R9），每条发现附汇编级证据。
3. **优化建议可信度评分**：统一的结构化评分（置信度/预期收益/风险/依据），依据字段引用
   真实动态计数与反汇编片段，取不到证据就不输出发现。
4. **性能—能效联合视角**：可配置权重的能耗估算分 Σ(类别动态计数 × 权重)，界面与报告强制
   附带免责声明（相对估算，仅用于优化前后趋势对比，不替代真实硬件功耗测试）。

### 5.2 R9 高光：同一浮点程序在三架构上的退化（b06，-O0 实测）

| 指标 | RV64GC（硬浮点） | RV64I（软浮点） | RV32I（软浮点） |
|---|---:|---:|---:|
| 动态指令总数 | 28,369 | 352,363 | 465,454 |
| 函数调用次数 | 164 | 4,537 | 7,735 |

无 F/D 扩展时 float 运算退化为 libgcc 软浮点例程（`__mulsf3` 等）：
RV64I 的动态指令数是 RV64GC 的 **12.4 倍**、调用次数 **27.7 倍**。
这是"面向 RISC-V 指令特征的优化"最直观的证明——同一算法，架构约束不同，最优写法不同。

### 5.3 编译等级的边界（b09，rv64gc 实测）

| 指标 | -O0 | -O2 | 变化率 |
|---|---:|---:|---:|
| 动态指令总数 | 46,318 | 9,075 | −80.4% |
| 函数调用次数 | 346 | 197 | −43.1% |

-O2 大幅削减指令量，但调用仅降四成——诚实展示"编译器已经做了什么"，而循环不变量外提、
算法级重复等源码级优化空间依然存在，且本平台能量化两者边界。

### 5.4 验证闭环实测（M5 达成记录）

端到端实测：两个基准走完 PROPOSED→ACCEPTED（如 strlen_loop 经 R1 取证 + 修改后
函数调用 5,406 → 5,106，动态指令 −300 条）；刻意构造的坏修改走完 REJECTED→回滚，
原因可读、证据保留。状态机四条路径（接受/编译失败/输出不一致/指标不降）集成测试全覆盖。

### 5.5 质量保证

- **166 个 pytest 用例**分层：单元层（不依赖工具链，含固定样例日志/异常容错）→ 集成层
  （真实 GCC/QEMU，缺失自动跳过）→ 回归层（10 基准 golden 比对 + 指标快照零浮动）；
- **确定性校验**：关键流程强制双运行比对，不一致即 NONDETERMINISTIC 中止；
- **一键自检**：`scripts\run_all_checks.bat` 全量复算（pytest + 10 基准 golden + 快照回归）。

## 6. 边界声明（诚实原则）

| 声明 | 说明 |
|---|---|
| 纯软件，无硬件 | 不测量、不声称测量任何真实芯片的功耗、温度、主频 |
| 能耗是估算 | 指令类别权重相对估算，仅用于趋势对比，界面与报告强制附免责声明 |
| TCG 不模拟缓存 | QEMU 为指令级模拟，缓存友好性只作静态提示，不作实测指标 |
| 主指标为动态指令数 | 确定性、可复核；墙上时间仅作参考值并标注 |
| 相对结论 | 结论限于同基准、同架构、同输入的对比，不外推为绝对性能 |

## 7. 复现指南

1. Windows 10/11 x64 + Python 3.10+：`python -m venv .venv && .venv\Scripts\activate &&
   pip install -r requirements.txt`；
2. 按 `docs/04-环境搭建指南.md` 安装 xPack GCC 与 QEMU（支持便携安装到 `tools\`）；
3. `pytest -m "not slow"` 快速自检；`scripts\run_all_checks.bat` 全量复算；
4. `.venv\Scripts\streamlit run app.py` 启动网页；LLM 功能在界面「优化建议」面板填写 DeepSeek API Key 后启用
   （可选，缺省为规则引擎模式）。

## 8. 开发过程

单人 + AI 辅助开发，按 M0~M7 里程碑推进（`docs/05-开发路线图.md`），全部里程碑提前于

禁止估算；每个里程碑有 DoD 与 git tag；AI 生成代码逐段审查后合入（提示词清单见 05 文档
第 5 节，可作为"AI 辅助开发方法论"的展示素材）。
