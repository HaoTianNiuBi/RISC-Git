# 08 风险与对策

> 每个风险都给出触发条件（何时确认风险已成真）与降级方案。遇到问题先查本表，再动手改方案。

## 4. 合规与伦理

| 事项 | 处理 |
|---|---|
| 用户代码上传 LLM API 的隐私 | 界面上传区明示"源码将发送至所配置的 LLM 服务商"；提供"仅规则引擎（不出网）"开关；凭据仅存本地 `.env` |
| 数据真实性承诺 | 全项目红线（README"数据红线"一节）；任何估算均显著标注；不在材料中声称未做过的测量 |
| 第三方工具许可 | gcc（GPL）、QEMU（GPL）等以 **subprocess 独立进程调用**，不链接其代码，本项目源码不受传染；材料中如实说明工具链来源与版本 |
| 学术诚信 | AI 辅助开发的部分在参赛材料中如实说明开发方式；核心创新（验证闭环、trace 统计）为本项目原创实现 |

## 5. 关键决策记录（ADR 摘要）

| 编号 | 决策 | 理由 | 放弃的替代方案 |
|---|---|---|---|
| D1 | Windows 原生环境（用户选定） | 无 WSL 依赖，贴近本人日常环境 | WSL2/qemu-user（列为升级路径）、Docker |
| D2 | qemu-system + semihosting + trace 解析作为动态统计主路线 | Windows 唯一可靠路径；结果确定可复现 | qemu-user + TCG 插件（Windows 无）、Spike（构建难）、纯静态估算（不真实） |
| D3 | 主指标 = 动态指令数，时间只作参考 | 确定性、可复核、可回归 | 墙钟时间（噪声大）、周期数（TCG 不提供） |
| D4 | LLM 用 Chat Completions 兼容可配置接口，凭据界面自填 | 接口标准化、密钥不落仓库，现场容错强 | 绑定单一厂商 SDK |
| D5 | 规则引擎与 LLM 双引擎 | 规则保下限（可解释、离线可用），LLM 拓上限 | 纯 LLM（不可控）、纯规则（创新性弱） |
| D6 | 文档驱动 + 里程碑 DoD + 数据红线 | 单人业余开发的执行纪律 | 边写边定（易烂尾） |
| D7 | 自研最小裸机运行时（不用 newlib specs）；计数范围 = 程序区（PC ≥ 0x80000000） | M0 实测：specs 半主机在 QEMU 11.1 失效；自研运行时行为确定可控，排除启动 ROM 中断竞态后计数 3 次运行完全一致 | semihost.specs / rdimon.specs（失效）、-Ttext 简易链接（HI20 越界） |

## 6. 风险检查节奏

- **每周日**：对照 05 文档里程碑 DoD，检查本周相关 T 风险是否触发；
- **M0 结束**：T1/T3/T4/T6 全部获得确定结论（这是 M0 存在的意义）；
- **M2 结束**：T2 定论（速度是否达标），未达标即锁定降级方案不再摇摆；
- **11-04（W8 首日）**：进行"交付 vs 裁剪"最终盘点，确定参赛材料范围。
