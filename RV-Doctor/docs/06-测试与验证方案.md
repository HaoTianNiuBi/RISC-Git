# 06 测试与验证方案

> 本文档定义指标口径、基准程序集、正确性/性能验证流程与验证闭环状态机。
> 数字红线：**界面与报告中出现的每一个数字都必须可溯源、可复算**。

---

## 1. 数据溯源原则（防编造红线）

1. **无证据，不展示**：任何指标先落盘（`metrics.json` 等），界面只读取落盘产物渲染，不现场"编"数字。
2. **证据链完整**：每个 task 的 `workdir/<task_id>/` 保留 `build.log`、`stdout.txt`、`trace.log`、`disasm.txt` 及各 JSON，报告注脚指明数据出自哪个文件。
3. **手工可复核**：抽查复核方法——`trace.log` 中 `Trace` 执行行计数 = 动态指令总数；`IN:` 反汇编行的助记符 = 类别分布来源；objdump 静态行数 = 静态指令数。
4. **LLM 零数字**：LLM 的上下文里数字全部来自实测 JSON，其输出中的任何数字仅作展示性引用，最终以复测为准。
5. **估算必须标注**：能耗分与相对时间在所有展示处标注"估算/参考"字样与免责声明。

## 2. 指标口径定义

| 指标 | 口径 | 性质 | 展示要求 |
|---|---|---|---|
| 动态指令总数 | 一次运行实际执行的指令条数（`-one-insn-per-tb` 下 Trace 执行行总数），**统计范围 = PC ≥ 0x80000000（程序+libc 区）**，启动 ROM 不计入（04 文档 M0 结论 5） | **主指标，确定性** | 原样展示 |
| 类别分布 | 助记符按 03 文档 5.5 节映射表归类后的动态计数 | 确定性 | 饼图 + 数值 |
| 分支 / 访存 / 调用 | 类别子集（branch、memory）与 jal/jalr 写 ra 计数 | 确定性 | 原样展示 |
| 静态指令数 | 反汇编代码段指令条数 | 确定性 | 原样展示 |
| 相对运行时间 | 同配置重复运行 N=5 取中位数；展示为相对基准版本的百分比 | **参考值**（TCG 墙钟受宿主负载影响） | 必须标"参考" |
| 能耗估算分 | Σ(类别动态计数 × 权重)，权重来自 config.toml | **相对估算** | 必须附免责声明 |
| 缓存友好性 | 仅静态提示（访存模式、步长），无实测值 | 提示 | 不得出现在指标表中 |

## 3. 基准程序集（b01~b10）规格

通用约定：编译期固定输入（常量数组或固定种子 LCG）、`printf` 输出校验和、golden stdout 存于 `benchmarks/expected/`；-O0 下动态指令约 10^4 ~ 5×10^6；每个程序头注释写明故意保留的可优化点。

| 编号 | 名称 | 算法核心 | 故意保留的可优化点 | 预期触发规则 | 预期实测变化方向（优化后） |
|---|---|---|---|---|---|
| b01 | sum_array | 数组累加 | 下标寻址每次重算地址；可改指针递增 + 2 路展开减分支 | R6/R7 | branch、address 计算类整数指令下降 |
| b02 | matrix_mul | N×N 乘法 | 内层 `a[i][k]`/`b[k][j]` 乘法寻址重复计算；k 循环内重复取 b 行 | R1/R2/R7 | 访存与地址整数指令下降 |
| b03 | crc32 | 位循环 CRC | 每位一分支；可改查表法 | R6 | branch 大幅下降，访存略升（总指令下降） |
| b04 | string_search | 朴素匹配 | 内层每轮重算边界、逐字符函数调用比较 | R1/R3 | 调用次数与分支下降 |
| b05 | bubble_sort | 冒泡排序 | 无提前退出标志；内层边界每轮重算 | R1/R6 | branch 与总指令下降 |
| b06 | grayscale | 浮点加权灰度 | float 权重 + 除法 → 可改整数移位近似 | **R9** | RV64I 下软浮点调用（`__mulsf3` 等）消失，指令数骤降（演示重点） |
| b07 | fib | 递归斐波那契 | 指数级重复递归 → 迭代/记忆化 | R3 | 调用次数与总指令数量级下降 |
| b08 | dot_product | 点积 | 每轮重复 load，可 4 路展开 | R2/R6 | load 与 branch 下降 |
| b09 | strlen_loop | 循环内 `strlen(s)` | 典型循环不变量外提（招牌用例） | R1 | 循环体内 call 清零，总指令显著下降 |
| b10 | window_sum | 滑动窗口求和 | 每个窗口从头累加 → 增量更新 | R1/R7 | 重复加法与访存下降 |

> 规格说明：优化点实现"修改候选"时存放在 `benchmarks/variants/<name>_opt.c`，作为无需 LLM 也能演示闭环的兜底素材（断网预案，见 07/08 文档）。

## 4. 正确性验证（golden stdout 比对）

1. 基准首次合入时，人工确认输出正确并固化为 `expected/<name>.out`；
2. 比对规则：两侧统一换行（`\r\n → \n`）后，忽略**末尾至多一个**换行差异，其余必须逐字符一致；
3. 比对失败 → 判 REJECT，`verdict.json` 记录首个差异行号与两侧片段（各截 200 字符）；
4. 用户上传的自有程序：以"优化前版本 stdout"作为 golden（优化只许改性能，不许改行为）。

## 5. 性能验证与确定性校验

1. **确定性校验**：同一 ELF 连续运行两次，`dynamic.total` 与 `by_class` 必须完全相等；不等则报 `NONDETERMINISTIC` 错误并中止流程（通常意味着 trace 解析有 bug 或环境异常）。
2. **性能对比口径**：优化前后必须**同架构、同优化等级、同输入**；对比值直接取两次实测 JSON，展示变化率 = (after − before) / before × 100%。
3. **时间参考值**：`wall_time_median_s` 仅在同类环境内相对比较；报告中不出现"快了 X 秒"的绝对表述，只出现"参考耗时比"。
4. **回归快照**：每个基准首次跑通后，将其 `metrics.json` 存为 `benchmarks/snapshots/<name>.json`；CI/自检时重跑比对（允许的浮动为零——指标是确定性的；若不一致即回归）。
5. **快照与源码的同源性（OpenMP 口径）**：`benchmarks/snapshots/` 与 `reports/data/` 的数字来自**不带** `-fopenmp` 的构建。`b02_matrix_mul.c` 内含

   ```c
   #ifdef _OPENMP
       #pragma omp parallel for schedule(static)
   #endif
   ```

   该宏只在编译命令显式带 `-fopenmp` 时定义，因此默认构建下源码行为与冻结快照等价；一旦用 `-fopenmp` 重编，**stdout 不变、动态指令数会变**（并行化改变指令构成），此时不能再拿冻结快照比对指令数。源文件 SHA256 `037c61c6…` 与 `板端验证/edge/results/b02-openmp-fixture.json` 记录的一致，说明 K1 夹具用的就是这份源码；该夹具只证明「在 K1 上能编译并正确并行执行」，其墙钟时间不与 QEMU 指令数混比。

## 6. 验证闭环状态机

```
              ┌────────────┐   编译失败    ┌───────────┐
              │ PROPOSED   ├──────────────►│           │
              └─────┬──────┘               │           │  恢复原版文件
                    │ 编译通过              │           │  保留失败证据
              ┌─────▼──────┐   输出不一致  │           │  verdict.json 记录原因
              │ COMPILED   ├──────────────►│ REJECTED  │
              └─────┬──────┘               │           │
                    │ stdout == golden      │           │
              ┌─────▼──────┐               │           │
              │ TESTED     ├──────────────►│           │
              └─────┬──────┘   指标未下降  └───────────┘
                    │ 指令数↓ 或 能耗分↓
              ┌─────▼──────┐
              │ MEASURED   │
              └─────┬──────┘
              ┌─────▼──────┐
              │ ACCEPTED   │ 生成对比报告，保留优化版
              └────────────┘
```

| 转移 | 条件 | 失败处置 |
|---|---|---|
| PROPOSED → COMPILED | 候选编译成功且生成 ELF | REJECT，记录 build.log 摘要 |
| COMPILED → TESTED | stdout 与 golden 一致 | REJECT，记录首个差异 |
| TESTED → MEASURED | 确定性校验通过（两次运行一致） | REJECT，标记 NONDETERMINISTIC |
| MEASURED → ACCEPTED | 动态指令数下降 **或** 能耗分下降 | REJECT，记录前后指标 |
| 任意状态异常（超时/崩溃） | — | REJECT，记录异常与现场 |

约定：ACCEPT 只保留**一个**最优候选（多个候选都通过时取动态指令数最小者，其余记为 rejected）；原版源码永不覆盖，优化版写入 `workdir/<task_id>/optimized/`。

## 7. pytest 测试分层

| 层 | 覆盖对象 | 用例示例 | 数量要求 |
|---|---|---|---|
| 单元 | trace_parser | 固定样例日志：正常解析 / 空日志 / 截断日志 / 异常行容错 / QEMU 8 vs 9 格式适配 | ≥ 5（对应 02 文档 NFR6） |
| 单元 | riscv_compile | 正常编译 / 语法错误 / 超时 / 非法 arch / objdump 缺失 | ≥ 5 |
| 单元 | disassemble、metrics、energy | 解析正确性、分类映射、权重快照 | ≥ 6 |
| 单元 | rules | 每条规则 1 正例 1 反例 | ≥ 18 |
| 单元 | llm_agent | mock HTTP：合法 JSON / 非法 JSON / 超时 / 未配置 | ≥ 4 |
| 集成 | verifier | 接受路径 / 编译失败 / 输出不一致 / 指标不降 | ≥ 4 |
| 集成 | pipeline | b09 端到端体检（需本机工具链，标记 `@pytest.mark.slow`） | ≥ 1 |
| 回归 | benchmarks | 10 个基准 golden stdout + 指标快照比对 | 10 × 2 |

分层策略：单元层不依赖工具链（CI 可跑）；集成与回归层依赖本机工具链，通过 marker 区分，一键脚本 `scripts\run_all_checks.bat` 全量执行。

## 8. 一键自检（M6 交付物）

```bat
scripts\run_all_checks.bat
:: 1) pytest（全层）
:: 2) 10 个基准 golden 比对
:: 3) 指标快照回归比对
:: 全绿输出 ALL CHECKS PASSED，任一失败给出首个失败项与证据路径
```

比赛材料中附该脚本运行截图/录屏，作为"数据真实、结果可复现"的直接证据。
