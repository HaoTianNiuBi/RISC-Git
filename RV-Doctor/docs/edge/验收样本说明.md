# K1 边缘终端验收样本说明

本文件与 `acceptance-cases.json` 定义后续验收的数据和计分规则。**当前只有文本定义；全部样本默认未录音、未测试，没有通过结果。** `expected_normalized` 由参考文字按规则生成，`expected_json` 是人工定义的期望值，两者都不是模型实测输出。实际结果应按 `run_id` 另行留存，不覆盖参考文本或 gold。

数据版本为 `rv-doctor-k1-edge-acceptance-v1`，定义日期为 2026-11-06。此前“喂喂喂”等收音冒烟录音只证明声音采集链路，不计入这套正式验收。

## 固定意图与前置条件

模型输出的最小协议为单个对象：`{"intent":"start_checkup"}`。只允许 `intent` 字段，枚举如下。

| intent | 任务 | 允许行为 |
|---|---|---|
| `start_checkup` | 开始体检，核心任务 | 进入已准备的固定体检任务 |
| `explain_report` | 解释报告，核心任务 | 解释固定的当前报告，以已测数据为依据 |
| `compare_configs` | 比较配置，核心任务 | 比较预置的四线程、八线程配置及结果 |
| `query_system` | 系统查询，辅助任务 | 读取本终端已定义的状态指标 |
| `unknown` | 超范围或信息不足 | 显示澄清或支持范围提示，不派发动作 |

这张表定义测试上下文，**不代表对应任务、报告、配置或运行入口已经准备完成**。正式测试前需固定这些上下文，并记录提示词、模型版本、推理参数、schema 版本及冷/热状态。配置结果缺失时必须明确提示，不能生成虚构数据。`intent` 不接受任意 Shell 命令；以后增加参数字段时须同步修改 schema 和数据版本。

## CER 规范化与计分

对参考文字与 ASR 原始识别文字分别执行以下顺序，所有样本使用同一规则：

1. Unicode `NFKC` 规范化。
2. 转小写，使用 Unicode `lower`。
3. 删除 Unicode 空白字符，即 `isspace` 为真的字符。
4. 删除 Unicode 一般类别以 `P` 开头的全部标点。
5. 其余字符保留原顺序，不做语义替换。

例如“比较４线程和８线程！”规范化为“比较4线程和8线程”。这只是规则示例，没有经过语音识别。**不把“四”与“4”视为相同字符，不做同义词、简繁体、语气词或错字纠正。** 因此 CER 与意图正确率可能给出不同结论，二者都须保留。

规范化后按字符计算 Levenshtein 编辑距离。设替换、删除、插入数为 S、D、I，参考字符数为 N，则 `CER = (S + D + I) / N`。十条语料的汇总值为 `sum(S + D + I) / sum(N)`，不能取十个 CER 的简单平均。规范化参考为空则样本无效；识别结果为空时，全部参考字符按删除计入；插入较多时 CER 可以大于 100%，不截断。

阶段一通过门槛：**十条全部录音并测试，汇总 CER ≤ 20%**。缺失、失败的样本不得从分母删除；任何必测项未完成时，只能报告未完成。

## JSON、意图与未知请求验收

阶段二对固定二十条分别计分：

- **JSON/schema 合法率为 100%**：原始输出恰好是一个 JSON 对象，允许前后空白，且符合 JSON 文件中的 `intent_output_schema`。代码围栏、附带解释、额外字段、重复键、NaN、Infinity 均不合格。
- **意图正确率至少 90%，即至少 18/20 条正确**：只有 JSON/schema 合格且 `intent` 与 gold 完全相同才计正确；解析失败、schema 不符、超时和缺失均计错误。分别报告各意图的正确数，不能只给总体百分比。
- **未知请求误执行一票失败**：四条未知用例中，只要任何一次派发了动作，整轮失败。不能用总体正确率抵消。

系统可在解析失败时安全回退到 `unknown`，但回退不能把原始无效输出“修成”一次合法或正确的模型回答。动作派发必须在解析及 schema 校验后，未知请求永不派发。

## 三种测试模式分开记录

| 模式 | 输入与范围 | 能支持的结论 |
|---|---|---|
| `text_intent` | 二十条参考文字直接输入意图模块 | 仅文本意图模块成绩，不代表 ASR 或音频端到端成绩 |
| `audio_asr` | 十条真实录音输入 ASR，计算 CER | ASR 文件识别成绩 |
| `audio_e2e` | 二十条真实录音，经音频输入、ASR、意图模块与受控派发观察 | 音频端到端成绩；意图模块必须使用 ASR 原始文本 |

若只测了文本二十条，不得写“二十条语音端到端通过”。若只录了十条 ASR 样本，也不得写二十条音频用例已经完成。人工修正转写文本再送模型的结果，可作为独立诊断记录，不能替代音频端到端成绩。

每轮冻结数据、提示词、schema、模型、参数和上下文，每例首次有效提交组成该轮成绩。重试或调整后另建 `run_id`，保留失败记录，不挑选最佳输出替换原轮。记录音频/文本来源、ASR 原始输出、规范化文本及编辑距离、模型原始 JSON、校验结果、意图、实际派发行为、首内容延迟、总耗时和冷/热状态。尚未实测的数字保持空值，不能填写预测值。
