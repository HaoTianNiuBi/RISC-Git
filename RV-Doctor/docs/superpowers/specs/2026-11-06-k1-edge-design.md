# RV-Doctor Edge 设计与验收口径

日期：2026-11-06（Asia/Shanghai）。状态：用户已在聊天确认总体方案，并明确要求“开始吧”。

## 目标和首版范围

将 RV-Doctor 改造为基于 K1 MUSE Pi Pro、Bianbu LXQt 的离线语音性能诊断终端。主链路为触屏控制录音、本地 ASR、本地 LLM 意图理解、受限任务执行、真机性能测量、配置候选复测和对比报告。

核心任务为 start_checkup（开始体检）、explain_report（解释报告）、compare_configs（比较配置）；query_system 为辅助查询，unknown 不触发任务。

复用现有任务目录、证据落盘、验证状态机思想、结构化模型接口和对比报告。原有 C/QEMU 工具保留，模拟指令数、能耗估算与 K1 真机数据分别标识。首版不要求由小模型自由生成 C 代码，也不要求同时接入摄像头、TTS 或运动机构。

## 已知基线

- 耳麦已由驱动检测，48 kHz/PCM16 采集成功；用户已确认回放中有人声。输入偏弱，预览副本放大 24 dB，原始录音保留。
- 采集设备使用稳定名称 hw:CARD=sndes8326,DEV=0，不能硬编码重启后可能改变的声卡编号。
- 已有 Qwen3.5-2B Q4_K_M 模型和 llama-server。一次 50 输入 token、7 输出 token 的探测得到首内容 12.723 秒、完整返回 15.609 秒。这不是稳定性或语音端到端基准。
- 板内尚无已验证的 ASR。官方独立组件的 K1 兼容性需要实际导入、模型加载和文件识别验证。

## 分阶段门槛

| 阶段 | 验收 |
|---|---|
| 0 范围与基线 | 保存设计、执行记录、验收样本定义和源文件基线；核对报名状态与提交清单。报名状态不能由代码测试推断。 |
| 1 本地 ASR | 先完成固定 WAV 的离线识别；再对 10 条真实短句录音按冻结规则计算汇总 CER，门槛 <=20%。组件导入或一次烟雾识别通过不等于整个阶段通过。 |
| 2 最小交互 | 20 条固定端到端样本至少 18 条任务正确；JSON/schema 合法率 100%；unknown 不得触发动作。触屏明确显示准备、录音中、识别中、模型处理中和结果。 |
| 3 真机测量 | 同一输入至少重复 3 次，记录 ASR、LLM 首内容/总耗时、任务执行和内存；保存配置、版本与原始结果，能够复算。 |
| 4 配置调优 | 每次只改变一个变量。正确率不下降且测量指标改善才接受，否则拒绝并保留证据；展示真实改善不预先保证收益。 |
| 5 交付 | 按部署说明可重新启动；连续 10 次现场交互不崩溃；空录音、无麦、模型失败能提示并回到可操作状态；GitHub 源码、方案/技术文档、部署与测试说明、演示视频完整。 |

端到端时延从停止录音计到任务结果显示，包含 ASR、LLM、执行和结果传递。模型启动时间单独记录；UI 提示“处理中”不视为 AI 响应完成。<=4 秒为争取的性能评分目标，未达到时如实报告。

阶段 1 设 1–2 小时可用性验证预算；遇到 SDK/模型不兼容时先记录原因并调整方案。没有真实录音、参考文本与识别输出时，不填写 CER 成绩。

## 组件边界

- 采集与音频准备：原始 48 kHz 双声道录音保留，识别输入转换为 16 kHz 单声道 PCM16；增益、裁剪和重采样参数进入清单。
- ASR：只将音频转换为文本及其测量结果，不执行任务。
- LLM：返回受限 JSON 意图或根据测量摘要解释，不提供被当成实测值的虚构性能数字。
- 执行器：仅接受已验证的意图和预定义任务。
- 测量/验证：负责真实耗时、正确性判断、配置候选接受/拒绝以及证据留存。
- 界面：由用户触控开始/结束录音，明确展示运行阶段和错误。

## 阶段 1 的实现约束

优先尝试官方 spacemit_asr 1.0.2 的 cp312/linux_riscv64 wheel，精确固定版本和 SHA256。在板端独立验证目录和 venv 中使用已安装的 NumPy/ORT/共享库。若二进制依赖或 API 不匹配，保留诊断，不以伪造库链接掩盖问题。源码 CPU file demo 为备用路线，不首先安装整套 sm-sdk 或升级操作系统。
