# 04 环境搭建指南（Windows 原生）

> 本文档指导在 **Windows 10/11 64 位**上从零搭建 RV-Doctor 所需的全部工具链，并完成里程碑 M0 的环境验证。
> 选型原因见 [03-系统架构设计](03-系统架构设计.md) 第 8 节；升级到 WSL2 的路径见本文附录 A。

---

## 1. 前置条件

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 1903+ / Windows 11，64 位 |
| 权限 | 安装软件需管理员权限 |
| 磁盘 | ≥ 3 GB 空余（工具链约 1 GB、QEMU 约 700 MB、工作产物若干） |
| 网络 | 下载安装包需要联网；LLM API 需要能访问所选服务商 |

## 2. 步骤一：Python 3.11+

1. 从 <https://www.python.org/downloads/> 安装 Python 3.11 或更高版本（项目配置使用标准库 `tomllib`），安装时勾选 **Add python.exe to PATH**。
2. 验证：

```bat
python --version
```

3. 建立项目虚拟环境（在仓库根目录）：

```bat
python -m venv .venv
.venv\Scripts\activate
```

4. 安装 `requirements.txt` 中的 Python 依赖：

```bat
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

| 包 | 用途 |
|---|---|
| streamlit | 网页界面 |
| plotly、pandas | 图表与数据 |
| pytest | 测试 |
| requests | 调用 DeepSeek 接口 |
| jsonschema | 校验 LLM 返回的优化建议 |

> ⚠️ 终端若显示中文乱码，先执行 `chcp 65001` 切换 UTF-8 代码页。

## 3. 步骤二：xPack RISC-V 交叉编译器

安装 **xPack GNU RISC-V Embedded GCC**（提供 `riscv-none-elf-gcc`、`riscv-none-elf-objdump` 等）。两种方式任选：

**方式 A（推荐）：xPack 包管理器 xpm**

```bat
npm install -g xpm           # 需要 Node.js 18+
xpm install --global @xpack-dev-tools/riscv-none-elf-gcc@latest
```

安装后位于 `%APPDATA%\xPacks\@xpack-dev-tools\riscv-none-elf-gcc\<版本>\.content\bin`，将该 `bin` 目录加入系统 PATH。

**方式 B：直接下载**

从 xPack 发布页 <https://github.com/xpack-dev-tools/riscv-none-elf-gcc-xpack/releases> 下载 `win32-x64` 压缩包，解压到如 `C:\Tools\xpack-riscv-none-elf-gcc`，将其中的 `bin` 目录加入 PATH。

**验证与登记：**

```bat
riscv-none-elf-gcc --version
riscv-none-elf-objdump --version
riscv-none-elf-gcc -print-multi-lib
```

- 把 `--version` 输出的版本号填入第 8 节"版本登记表"。
- `-print-multi-lib` 会列出编译器支持的 `-march/-mabi` 组合。确认其中包含本项目所需的三种组合，若某组合缺失，按 08 文档风险 T4 处理（调整支持矩阵，不硬凑）。

## 4. 步骤三：QEMU for Windows

1. 从 <https://qemu.weilnetz.de/w64/> 下载 QEMU Windows 安装包（社区标准 Windows 构建，含 `qemu-system-riscv64.exe` / `qemu-system-riscv32.exe`），安装到默认或自定义目录（如 `C:\Program Files\qemu`）。
2. 将安装目录加入 PATH。
3. 验证并登记版本：

```bat
qemu-system-riscv64 --version
qemu-system-riscv32 --version
```

> ⚠️ **版本锁定**：trace 日志格式与 QEMU 版本相关。安装后在第 8 节登记表中记录精确版本号，开发期间不要随意升级 QEMU（08 风险 T1）。
>
> ⚠️ **逐条执行参数随版本变化（M0 实测）**：QEMU ≥ 10 已移除 `-singlestep` 与独立参数 `-one-insn-per-tb`，改为 **`-accel tcg,one-insn-per-tb=on`**；QEMU 8.1~9.x 用独立参数 `-one-insn-per-tb`；更早版本用 `-singlestep`。`runner.py` 实现时按"accel 属性 → 独立参数 → singlestep"顺序探测。本项目实测版本 11.1.0，使用 accel 属性写法。

## 5. 步骤四：环境验证（M0 验收内容）

以下 5 项全部通过，即完成 M0。命令在仓库根目录执行，测试源码使用 `tests\fixtures\environment\hello.c`，生成的 ELF、反汇编与日志统一放入 `workdir\environment\`：

```bat
if not exist workdir\environment mkdir workdir\environment
```

### 5.1 测试源码 `tests\fixtures\environment\hello.c`

仓库已提供此样例，内容如下：

```c
#include <stdio.h>

int main(void) {
    int sum = 0;
    for (int i = 1; i <= 100; i++) {
        sum += i;
    }
    printf("sum=%d\n", sum);   /* 预期输出 sum=5050 */
    return 0;
}
```

### 5.2 编译（裸机 + 半主机运行时）

```bat
riscv-none-elf-gcc -march=rv64gc -mabi=lp64d -O0 ^
  -mcmodel=medany -msmall-data-limit=0 -nostartfiles ^
  --specs=semihost.specs -Wl,--no-warn-rwx-segments ^
  -Tcompiler\link.ld compiler\rvcrt0.S ^
  tests\fixtures\environment\hello.c -o workdir\environment\hello.elf
```

参数说明：

| 参数 | 作用 |
|---|---|
| `-march/-mabi` | 目标 ISA 与 ABI（对应界面上的架构选项） |
| `--specs=semihost.specs` | 链接当前 xPack 工具链提供的半主机运行时，printf/exit 走 semihosting；旧工具链若仅提供 `rdimon.specs`，替换此参数。项目的 `compile_source` 会自动探测 |
| `-mcmodel=medany` | 允许 RV64 访问位于 0x80000000 的程序段与数据 |
| `-nostartfiles`、`compiler\rvcrt0.S` | 使用项目启动代码初始化 gp、sp 与 BSS，避免默认 crt0 假定已有固件初始化 |
| `-Tcompiler\link.ld` | 把程序各段、堆与栈放入 `virt` 机器 DRAM 区间 |
| `-msmall-data-limit=0` | 与项目编译器封装一致，避免大型全局数据超出 gp 相对寻址范围 |

### 5.3 运行（QEMU 裸机 + semihosting）

```bat
qemu-system-riscv64 -M virt -nographic -bios none ^
  -semihosting-config enable=on,target=native ^
  -kernel workdir\environment\hello.elf
```

**预期**：终端输出 `sum=5050`，程序结束后 QEMU 自动退出（exit 走半主机 SYS_EXIT）。
**退出技巧**：若 QEMU 挂住不退出，按 `Ctrl-A` 再按 `X` 退出。

### 5.4 反汇编

```bat
riscv-none-elf-objdump -d workdir\environment\hello.elf > workdir\environment\disasm.txt
```

**预期**：文件中能看到 `main:` 函数与 `addi`、`lw/sp` 等指令；`printf` 显示为对 `printf`/semihosting 相关符号的调用。

### 5.5 trace 日志试跑（精确计数原型）

```bat
qemu-system-riscv64 -M virt -nographic -bios none ^
  -semihosting-config enable=on,target=native ^
  -accel tcg,one-insn-per-tb=on -d in_asm,exec,nochain -D workdir\environment\qemu.log ^
  -kernel workdir\environment\hello.elf
```

> QEMU ≥ 10 用 `-accel tcg,one-insn-per-tb=on`；8.1~9.x 改写为独立参数 `-one-insn-per-tb`（见第 4 节版本说明）。

**预期**：`workdir\environment\qemu.log` 生成，其中：
- `IN:` 段落出现 `0x……:  addi …` 之类的反汇编行（PC → 助记符来源）；
- `Trace …:` 行与实际执行一一对应（动态执行计数的来源）；
- 日志行数与循环规模同量级（100 次循环 → 数千行以内）。

用 Python 快速抽样确认格式可解析（此脚本仅验证环境，正式解析器见 `profiler/trace_parser.py`）：

```python
from pathlib import Path
text = Path(r"workdir\environment\qemu.log").read_text(encoding="utf-8", errors="replace")
ins = [l for l in text.splitlines() if l.startswith("Trace")]
print("exec 记录数:", len(ins))     # 预期 > 0
print("in_asm 段存在:", "IN:" in text)
```

- [ ] `-print-multi-lib` 覆盖 RV32I/RV64I/RV64GC 所需组合（缺失已按 T4 记录对策）；
- [ ] `qemu-system-riscv64 --version` 正常，版本已登记；
- [ ] hello.c 编译 → 运行输出 `sum=5050` → 反汇编 → trace 日志生成，四步全通；
- [ ] 32 位冒烟：`-march=rv32i -mabi=ilp32` 编译同一程序并用 `qemu-system-riscv32` 跑通（若 ilp32 组合 multilib 不含，记录并按 T4 调整）。

## 6. 常见问题（FAQ）

| 现象 | 原因与处理 |
|---|---|
| QEMU 报 `Could not load kernel …` / ELF 加载失败 | 链接地址不在 `virt` DRAM 区间（0x80000000 起）。使用项目配套 `compiler/link.ld`，不要只设置 `-Ttext` |
| 编译报 `cannot find specs`/`rdimon` 相关错误 | **M1 实测**：xPack GCC 15.2.0-1 已不附 `rdimon.specs`，应使用 `semihost.specs`（配套 `libsemihost.a`，QEMU 11.1 下实测正常工作，见第 9 节结论 1 更正）。`compile_source` 已封装自动探测（rdimon → semihost） |
| `-Ttext=0x80000000` 报 `R_RISCV_HI20 truncated`；或运行时卡死在取指 fault 死循环 | **M1 实测两个坑**：① RV64 默认 medlow 代码模型 LUI 绝对寻址够不到 0x80000000 以上符号，需 `-mcmodel=medany`；② newlib crt0 假定固件已设好 sp，`-bios none` 下 sp=0，第一条栈操作即 store fault，且 mtvec=0 死循环。`compiler/rvcrt0.S` + `compiler/link.ld` 已统一解决并由 `compile_source` 封装，不要再手工拼 -Ttext 命令 |
| 手写的半主机 ebreak 序列不被 QEMU 识别（打印/退出失效） | 汇编器会把 `ebreak` 压缩成 `c.ebreak`（0x9002），QEMU 11.1 的魔法序列识别只认 4 字节 `ebreak` 的相邻编码布局（M1 实测：c.ebreak 下 SYS_WRITE0/SYS_EXIT 全部失效）。手写序列必须 `.option norvc` 包裹；libgloss 预编译调用点已按 nop 对齐成 4 字节序列，无需处理 |
| `-print-multi-lib` 缺少目标组合 | multilib 不含该 march/mabi → 调整界面"架构选项"为实际可用的集合（08 风险 T4），不要强凑。**M1 实测**：15.2.0-1 覆盖 rv32i/ilp32、rv64i/lp64、rv64imafdc_zicsr/lp64d（即 rv64gc）三组，T4 无需触发 |
| 程序运行卡住不退出 | semihosting 未开启（漏 `-semihosting-config`），或程序死循环；先用 `Ctrl-A X` 退出，检查源码 |
| 中文路径导致工具报错 | 统一使用 `pathlib` 与短 ASCII 工作路径（如 `C:\rvd\workdir`），源码路径避免中文空格（NFR3）。objdump 按 ANSI 代码页回显含中文的路径，解析时用 `errors="replace"` 即可（tests 已覆盖） |
| trace 日志巨大 | 属预期；基准规模控制 + `-D` 落盘流式解析（03 文档第 9 节） |

## 7. 附录 A：WSL2 升级路径（性能更好，非必需）

当后续需要更大规模基准时，可迁移到 WSL2 + qemu-user + TCG 插件路线：

```bash
# WSL2 Ubuntu 内
sudo apt update && sudo apt install -y gcc-riscv64-linux-gnu qemu-user qemu-user-static
# 编译 Linux ELF
riscv64-linux-gnu-gcc -static -O0 sum.c -o sum
# TCG 插件精确计数（QEMU 7+，插件源码在 QEMU 源树 contrib/plugins 编译）
qemu-riscv64 -plugin /path/to/libinsn.so ./sum
```

架构上只需替换 `profiler/runner.py` 与 `trace_parser.py` 的实现，接口不变（03 文档第 8 节）。MVP 阶段**不依赖**此路线。

## 9. M0 实测结论（2026-09-16，重要坑位记录）

以下问题在 M0 环境验证中全部实际遇到并解决，对应 08 文档 T3，**后继模块开发必须遵守这些结论**：

1. **`rdimon.specs` 不存在**：xPack GCC 15.2.0 的新版 newlib 只提供 `semihost.specs`（配套 `libsemihost.a`）。
   **更正（M1 实测，2026-09-17）**：`semihost.specs` 在 QEMU 11.1 下**可以正常工作**。此前"ebreak 落入异常死循环"实为两个独立问题叠加：① **sp=0**——newlib crt0 假定引导固件已设好栈指针，`-bios none` 下无人设置，第一条栈操作即 store fault（mtvec 亦为 0，反复取指 fault），与半主机识别无关；② 若是**手写**的半主机序列，汇编器会压缩成 `c.ebreak`，QEMU 识别失配（4 字节 ebreak 序列实测正常）。
   **M1 定稿实现**：`compile_source` = 自带 `compiler/rvcrt0.S`（自设 gp/sp、写 mtimecmp 消噪、清 bss、init_array、调 main→exit）+ `compiler/link.ld` + specs 自动探测（rdimon → semihost），保留 newlib `printf`（P3 基准规格依赖）。hello.c 于 rv64gc/rv32i 双架构实测 `sum=5050` + 正常退出（产物 `workdir\m1_matrix\`，30/30 全过）。另一份同日并行探索的自研运行时已归档到 `docs/archive/runtime-experiments/runtime.*`，配套探针和链接脚本也保存在该目录；这些实验未接入 `compile_source`，仅供历史复盘。
2. **`-mcmodel=medany` 必须加**：默认 medlow 只能寻址 ±2 GB，链接到 0x80000000 会报 `relocation truncated to fit: R_RISCV_HI20`。
3. **gp 必须最先初始化**，且要用 `.option norelax` 包裹 `la gp, __global_pointer$`，否则松弛后 gp=0，第一次 BSS 清零存储即 `fault_store`（M0 实测：`tval=0x470` 即立即数本身）。
4. **定时器中断噪声**：`-bios none` 下无人设置 `mtimecmp`，MTIP 常挂起，与 QEMU TB 链产生宿主机时序竞态，trace 计数 ±2 抖动（`Stopped execution of TB chain`）。运行时初始化须把 CLINT `mtimecmp`（0x02004000）写为最大值。
5. **统计口径（写进 06 指标定义）**：动态指令计数只统计 **PC ≥ 0x80000000（程序+libc 区）**，启动 ROM（0x1000 区固定几条 + 中断竞态重执行）不计。实测 3 次运行程序区计数完全一致（hello O0：4071 条）。
6. **链接脚本**：`-Wl,-Ttext=0x80000000` 不够（.rodata 留在默认位置导致 HI20 越界），必须使用完整 `link.ld`（MEMORY 覆盖 0x80000000+128M，提供 `__global_pointer$`/`__bss_start`/`__bss_end`/`__stack_top`）。
