## 3. 里程碑详表

### M0（W1）环境与验证

- **目标**：Windows 工具链全部就绪，半主机裸机流程手动跑通。
- **任务**：按 [04-环境搭建指南](04-环境搭建指南.md) 完成步骤一~四；填写版本登记表；`git init` 建仓（开源备赛需 GitHub，见 08 文档）；提交 `requirements.txt` 初版。
- **DoD**：04 文档 5.6 节验收清单 5 项全部勾选。

### M1（W2）编译模块 + 静态分析

- **目标**：`compiler/` 两模块完成并有测试。
- **任务**：`riscv_compile.py`（参数表映射、subprocess 列表调用、日志落盘、错误结构化）；`disassemble.py`（objdump 解析、静态统计）；`tests/` 单测（≥ 5 个：正常编译、语法错误、超时、非法 arch、objdump 缺失报错）。
- **DoD**：10 个基准占位程序（此时可先用 2 个简单 .c）在 3 架构 × 5 优化等级下编译出 ELF 且静态统计正确；pytest 全绿。

### M2（W3）运行 + 动态指令统计 ★关口

- **目标**：拿到**真实**动态指令数与类别分布。
- **任务**：`runner.py`（QEMU 进程管理、超时强杀、stdout 捕获、trace 开关）；`trace_parser.py`（in_asm/exec 解析，含固定样例日志测试 ≥ 5 个用例）；`metrics.py`（聚合为 MetricsReport）；确定性校验（同 ELF 两次运行指标必须完全一致）。
- **DoD**：任一基准产出 `metrics.json`，动态指令总数与手工抽查（挑 3 个函数数日志行）一致；运行两次结果 bit 级一致；全程耗时在 NFR4 内。

### M3（W4）基准集 + 界面打通

- **目标**：10 个内置基准全部真实可跑；网页能完成一次"体检"。
- **任务**：按 06 文档规格实现 b01~b10 及 `expected/` golden 输出；Streamlit 首页（输入、架构/优化选择、体检按钮、指标卡片、类别分布饼图、Top 函数条形图）；能耗估算 `energy.py` 接入。
- **DoD**：网页上传 b01 → 一键体检 → 全部数字来自 M1/M2 真实数据；10 个基准 golden 比对全部通过。

### M4（W5）规则引擎

- **任务**：`rules.py` 实现 R1~R9（见 03 文档 5.7 节表）；每条规则配 1 个"必然触发"的基准用例。
- **DoD**：10 个基准至少各触发 1 条规则，发现项四要素（位置/证据/建议/评分）齐全且证据真实；`rules.py` 单测覆盖每条规则正反例。

### M5（W6）LLM 建议 + 自动验证闭环 ★核心创新

- **状态：✅ 已完成（2026-09-17，提前于排期）**
- **任务**：`llm_agent.py`（DeepSeek 接口调用、Schema 校验、降级开关）；`verifier.py`（状态机、golden 比对、指标对比、ACCEPT/REJECT 与回滚）；刻意构造 1 个坏修改验证回滚路径。
- **DoD**：≥ 2 个基准走完 PROPOSED→ACCEPTED 且报告中前后对比真实；1 个坏修改走完 REJECTED→回滚且原因可读；断网状态下降级为纯规则模式可用。
- **达成记录**：14 个新测试全绿（llm_agent 9 离线 mock + verifier 5 真实工具链，四条状态机路径全覆盖含回滚恢复实测）；端到端演示 `scripts/m5_demo.py` 两个基准（b09 式 strlen_loop 经 R1 取证 + square 内联）均 ACCEPTED（calls 5406→5106，-300 条实测指令）；未配置 API 时自动降级并附可读原因。真实 LLM API 冒烟待配置 key 后执行（不阻塞）。

### M6（W7）报告与打磨

- **任务**：`reports/report.py` 对比报告（指标表 + 变化率 + 数据来源注脚 + 免责声明）；图表美化；全量 pytest + `scripts\run_all_checks.bat` 一键自检；README 与截图更新。
- **DoD**：一键脚本全绿；三个演示基准（b02/b09/b06）的报告可直接用于录屏。

### M7（W8）参赛材料

- **任务**：按大赛官网要求整理技术文档（可复用本 docs/ 体系精简）；录制演示视频（脚本见 07 文档）；完成线上报名信息确认；若要求开源，整理 GitHub 仓库（License、README、commit 规范）。
- **DoD**：报名状态"已提交"；材料本地双备份（网盘 + 移动硬盘）。

## 4. 裁剪策略（延期时砍什么）

优先级从低到高砍，**验证闭环与真实数据永不砍**：

1. 砍 FR9 热点函数排名、FR7 编译参数推荐（M3~M4 未达时）；
2. 砍图表美化、批量跑分 FR8（M6 未达时）；
3. 砍能耗分可视化细节（保留 JSON 与报告中的数值，展示从简）；
4. **保留**：编译 → 运行 → 真实动态指令数 → 规则引擎 → 验证闭环 → 对比报告，这是项目的灵魂。

## 5. AI 辅助开发提示词清单

> 用法：每个里程碑开始时，把对应提示词交给 AI 生成代码，然后**逐段审查后再合入**。提示词中反复强调的两条纪律：subprocess 参数列表调用；不得伪造任何性能数据。

### P0 项目设计（已使用，产出本文档体系）

见项目缘起材料；对应产出即本 `docs/` 目录。

### P1（M1 用）生成编译模块

```text
你是一名熟悉 Windows 与 RISC-V 工具链的 Python 工程专家。请为 RV-Doctor 编写
compiler/riscv_compile.py 和 compiler/disassemble.py：

1. compile_source(src, arch, opt, workdir, timeout) 调用 riscv-none-elf-gcc：
   支持 arch ∈ {rv32i: ilp32, rv64i: lp64, rv64gc: lp64d}，opt ∈ {O0..Os}；
   自动附加 --specs=rdimon.specs 与 -Wl,-Ttext=0x80000000；
2. 必须用 subprocess 参数列表方式调用，禁止 shell=True；
3. 编译日志写入 workdir/build.log；错误返回结构化 CompileResult；
4. disassemble.py 调用 riscv-none-elf-objdump -d 并解析出：指令总数、
   按助记符统计、函数列表及每函数指令数；
5. objdump 不存在时抛出带安装提示的 ToolchainError；
6. 所有路径用 pathlib，兼容中文与空格；
7. 不要伪造任何数据；统计必须来自真实解析；
8. 为每个文件提供 pytest 单元测试，并说明在 Windows 上如何运行。
```

### P2（M2 用）运行与 trace 解析

```text
请为 RV-Doctor 编写 profiler/runner.py、trace_parser.py、metrics.py：

1. run_baremetal(elf, workdir, timeout) 调用 qemu-system-riscv64/32：
   参数 -M virt -nographic -bios none -semihosting-config enable=on,target=native
   -accel tcg,one-insn-per-tb=on -d in_asm,exec,nochain -D trace.log -kernel elf；
   逐条执行参数按版本探测（≥10 用 accel 属性，8.1~9.x 用 -one-insn-per-tb）；
   超时强杀进程树并标记 timed_out；
2. parse_trace 解析 trace.log：IN: 段建立 PC→助记符映射，Trace 行统计
   每个 PC 执行次数；解析格式做成独立适配函数，便于 QEMU 版本适配；
3. metrics.py 聚合静态+动态指标为文档定义的 MetricsReport JSON，
   指令分类映射表（integer/memory/branch/jump/muldiv/float/system）独立可配；
4. 禁止估算：所有数字必须来自日志解析；解析器要有基于固定样例日志的
   pytest 用例至少 5 个（含空日志、截断日志、异常行容错）。
```

### P3（M3 用）基准集

```text
请为 RV-Doctor 生成 10 个用于 RISC-V 性能分析的 C 基准程序
（b01_sum_array、b02_matrix_mul、b03_crc32、b04_string_search、
b05_bubble_sort、b06_grayscale、b07_fib、b08_dot_product、
b09_strlen_loop、b10_window_sum）：

1. 每个程序使用编译期固定的输入（常量数组或固定种子的 LCG），
   main 中打印可验证的校验和与结果；
2. 规模控制：-O0 下动态指令数约 10^4 ~ 5×10^6；
3. 每个程序故意保留 1~2 个可优化点（见 06 文档基准规格表），
   并在文件头注释中说明该可优化点与预期触发规则；
4. 仅用标准 C（freestanding 友好，printf/退出即可），不用平台相关库；
5. 每个程序给出期望 stdout 样例，存为 benchmarks/expected/<name>.out；
6. 输出对 RV64I（无浮点硬件）友好；b06 允许使用 float 以演示软浮点退化。
```

### P4（M3 用）界面骨架

```text
请为 RV-Doctor 编写 Streamlit 网页 app.py 与 pipeline.py：

1. 侧边栏：源码粘贴框 / 文件上传（.c .cpp .s .elf）、架构选择
  （RV32I/RV64I/RV64GC）、优化等级（-O0..-Os）；
2. 主区按钮"RISC-V 性能体检"：依次调用 pipeline（编译→反汇编→运行→
   统计→能耗），展示指标卡片、指令类别饼图（Plotly）、Top 函数条形图；
3. 每步失败时用 st.error 显示结构化错误与日志路径，不中断会话；
4. 每次任务建立独立 workdir/<task_id>/，全部产物落盘；
5. 本阶段不接 LLM；AI 建议区域先放占位提示"待 M5 接入"；
6. 界面展示的任何数字必须来自 pipeline 返回的真实 JSON，不得造数。
```

### P5（M4 用）规则引擎

```text
请编写 optimizer/rules.py，实现 9 条规则（R1 循环不变量重复计算、
R2 循环内重复读取不变内存、R3 高频函数调用、R4 编译等级不足、
R5 冗余类型转换、R6 分支密集、R7 重复内存访问、R8 寄存器溢出、
R9 软浮点退化），每条输出 Finding JSON（编号、位置、说明、
RISC-V 汇编证据、建议、风险、预期收益、置信度）：

1. 只读分析，绝不修改源码；
2. 证据字段必须引用真实反汇编片段或真实计数，无法取证时不输出该发现；
3. R4 通过"同码换 -O2 实测"取证，属于最慢的规则，提供开关；
4. 每条规则至少一个正例基准（必然触发）与一个反例（不触发）pytest 用例。
```

### P6（M5 用）LLM 建议模块（补全原第七步）

```text
请编写 optimizer/llm_agent.py：

1. 通过 DeepSeek 接口调用 LLM：base_url/api_key/model 由调用方传入（界面填写，仅存会话内存）；
2. 输入上下文：源码、关键函数反汇编摘录（截断至 N 行）、MetricsReport
   JSON、规则引擎 findings；明确告诉模型"所有数字已给出，禁止自行估算
   或编造任何数字"；
3. 要求模型只输出 JSON 数组（建议标题、位置、修改说明、完整修改后源码、
   预期收益、风险、置信度），用 jsonschema 校验，不合法即丢弃并记录；
4. LLM 不直接写文件，只返回候选源码，由调用方交给 verifier；
5. 未配置 API 或请求失败时返回空列表并附带降级原因；
6. 提供离线单测（mock HTTP），不打真实 API。
```

### P7（M5 用）自动验证闭环（补全原第八步）

```text
请编写 optimizer/verifier.py：

1. 状态机 PROPOSED→COMPILED→TESTED→MEASURED→ACCEPTED/REJECTED，
   状态轨迹完整记录到 verdict.json；
2. 对候选源码依次：编译（复用 riscv_compile）→ 运行（复用 runner）→
   stdout 与 golden/原版逐字符比对（统一 \r\n，忽略尾部单个换行）→
   重新统计动态指令 → 判定；
3. ACCEPT 条件：编译成功 且 输出一致 且（动态指令数下降 或 能耗分下降）；
   否则 REJECT，恢复原版文件，记录失败原因与全部证据；
4. 任何一步异常都要落盘现场，绝不静默吞错；
5. 提供 pytest：正常接受路径、编译失败路径、输出不一致路径、
   指标不降路径，共 4 条路径的集成测试。
```

```text
能耗分、变化率）、结论、数据来源注脚（task_id、工具版本、产物文件名）、
能耗免责声明与"TCG 不模拟缓存"边界声明。表格数字只能取自两份 JSON。
```
